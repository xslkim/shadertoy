screen 1 · 痛点

传统描述符模型  vs  Descriptor Heap

为什么需要一个新模型

传统模型 · 绑定时代

1
创建 DescriptorPool
↓
2
分配 DescriptorSet(形状由 layout 决定)
↓
3
vkUpdateDescriptorSets 写入真实资源
↓
4
vkCmdBindDescriptorSets 每次绘制绑定

⚠ 资源组合一变就换 layout/set;海量资源切换成本高

堆模型 · 索引时代

1
建一块全局 堆 (heap)
↓
2
所有资源描述符紧密排进堆里
↓
3
绑定整块堆(整帧一次)
↓
4
shader 拿 索引 直接到堆里取资源

✓ 一帧内随手访问任意资源 —— 真正的 bindless

screen 2 · 演进

Vulkan 走向 Bindless 的三步

descriptor_heap 不是凭空出现的
VULKAN 1.2 CORE

descriptor_indexing

shader 可用非一致索引访问描述符数组。bindless 的雏形,但描述符仍绑在 set 里。

→
VK_EXT

descriptor_buffer

描述符变成普通数据,写进 buffer 用 GPU 地址绑定。本 demo 实际用它出画面。

→
VK_EXT · 本期主角

descriptor_heap

一块全局堆 + 一张映射表,shader 由索引直接定位资源。对齐 D3D12 / SM6.6。

screen 3 · 核心

一个堆,一个索引

CPU 每帧只推送一个整数,shader 自己去堆里取(下方为动画演示)
#0🔴scene 0
#1🔵scene 1
#2🟣scene 2
#3🟢scene 3
#4🟠scene 4
#5🟦scene 5
↑ Resource Heap:每个槽位 = 一个描述符(本 demo 中 8 字节),紧密排列
CPU: vkCmdPushDataEXT → push index = 0
→
GPU shader: heap[ 0 ]
→
取出资源 scene 0 上色
索引来源可以是 push 常量 / 间接 buffer / shader record…… 本 demo 用最直观的 HEAP_WITH_PUSH_INDEX_EXT。
screen 4 · API

descriptor_heap 工作流 · 六步

对照 src/descriptor_heap_reference.cpp
1
开启特性   VkPhysicalDeviceDescriptorHeapFeaturesEXT.descriptorHeap = VK_TRUE
2
查描述符尺寸   vkGetPhysicalDeviceDescriptorSizeEXT → 算出堆要多大
3
创建堆 buffer   usage = VK_BUFFER_USAGE_DESCRIPTOR_HEAP_BIT_EXT
4
写描述符进堆   vkWriteResourceDescriptorsEXT / ...SamplerDescriptorsEXT
5
建映射表(灵魂)   VkDescriptorSetAndBindingMappingEXT → source = HEAP_WITH_PUSH_INDEX
6
录命令   vkCmdBindResourceHeapEXT + vkCmdPushDataEXT + vkCmdDraw
对照本 demo 实跑的 descriptor_buffer:绑堆 ↔ vkCmdBindDescriptorBuffersEXT, push 索引 ↔ vkCmdPushConstants。心智模型一致。
