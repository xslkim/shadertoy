# 程序化植被资产生成 —— 实现说明与 Agent 作业手册

> **这份文档写给谁**：接到"这里有一个参考 FBX，做一个能批量生成同规格资产的生成器"任务的 AI agent。
>
> **前置产物**：`自动化生成树模型调研.md` 记录了为什么选这条路线（以及为什么现成工具都不合适）。本文档只讲**怎么做**。
>
> **已跑通的样板**：针叶松树。参考 `mesh/IL3DN_Tree_Pine_01_OneMesh.FBX`，生成器 `tools/pine_gen.py`，端到端 156 ms/棵。后续所有品类照这个模式复制。

---

## 0. 一句话方法论

**不要造通用树生成器。每个品类抄一份 `pine_gen.py` 改。**

这是整个手册最重要的一条。通用生成器的参数空间会爆炸，而且每次都在和"这个品类不需要的抽象"搏斗。实际情况是：一个品类的生成器只有 300~400 行，其中真正品类特有的骨架逻辑只有 100 行左右，剩下的（网格容器、管状体、卡片、顶点色、LOD 分档、FBX 写出、渲染验收）全是可以直接复用的基础设施。

复制 300 行比维护一个万能参数系统便宜得多。

---

## 1. 为什么这件事比看起来简单

低模植被资产的几何复杂度被严重高估了。逆向参考资产之后发现，一棵 2076 三角面的松树只用了**两个几何原语**：

1. **锥形管**（tapered tube）—— 主干、枝条。沿一条折线生成环，环之间连四边形。
2. **V 形对折卡片**（folded card）—— 叶簇。6 个顶点 / 2 个四边形，一条脊线加两个翼。

草、花、灌木也逃不出这个范围，最多再加一两个原语（见 §6）。

真正需要认真对待的不是几何，而是**资产契约**：坐标系、单位、材质槽顺序、UV 布局、顶点色语义、LOD 命名。这些东西在生成时是免费的（你就这么建），事后改造是昂贵的（要重拓扑）。所以第一阶段的逆向分析必须做扎实。

## 2. 代码分层

```
tools/
├─ 复用层（新品类不要改）
│   inspect_fbx.py        最小 FBX 二进制解析器（读）
│   fbx_writer.py         最小 FBX 二进制写出器（写，FBX 7300）
│   render_hq.py          带贴图/阴影/抗锯齿的软件渲染器
│   softrender.py         纯色平面着色渲染器（快速预览用）
│
├─ 分析层（复用，按品类扩展判据）
│   analyze_tree_fbx.py   拓扑 / UV / 顶点色语义分析
│   analyze_layout.py     骨架布局规律提取（轮生层、包络、卡片朝向）
│   validate_with_ufbx.py 第三方加载器独立校验
│
└─ 品类层（每个新品类新写一份）

    build_pine.py         ← 样板：端到端流水线 + 断言
    gen_tree_textures.py  ← 样板：程序化贴图
    render_scenes.py      ← 样板：出图脚本
```

**当第二个品类落地时**，把 `pine_gen.py` 里这几个下划线开头的函数抽到共用模块 `tools/veg_core.py`，它们和树种无关：

| 函数 | 作用 |
|---|---|
| `TreeMesh` | 四边形网格容器（重命名为 `VegMesh` 更贴切） |
| `_normalize` / `_frame` | 向量归一化 / 构造正交基 |
| `_tube` | 锥形管，全四边形，带平行传输防扭转 |
| `_leaf_card` | V 形对折双 quad 卡片 |
| `_wind_color` | 顶点色风数据编码 |

在那之前直接 `from pine_gen import TreeMesh, _tube, _leaf_card` 也能跑，只是不体面。

## 3. 资产契约（所有品类必须遵守）

这一节是硬约束。偏离任何一条都会让下游（引擎导入、shader、LODGroup）出问题。

| 项目 | 约定 | 在哪里落实 |
|---|---|---|
| **生成期坐标系** | Z-up，米，根部在 z=0，原点在树心 | 生成器内部 |
| **导出期坐标系** | Y-up，厘米。转换式 `(x, y, z)m → (100x, 100z, -100y)cm` | `build_*.py: to_fbx_payload()` |
| **单位声明** | `UnitScaleFactor = 1.0`（即 1 单位 = 1 cm） | `export_lod_fbx(unit_scale_cm=1.0)` |
| **拓扑** | **全四边形**，不出三角面、不出 n-gon | 生成器；`verify()` 断言 |
| **材质槽** | 槽 0 = 木质（bark/stem），槽 1 = 叶片（leaf/petal）。顺序固定 | `MAT_BARK=0, MAT_LEAF=1` |
| **UV 通道** | 单通道，名字 `UVChannel_1` | `fbx_writer._geometry_node()` |
| **树皮 UV** | U ∈ [0.02, 0.98] 绕管一圈，V 沿长度累积（可平铺） | `_tube(u0=0.02, u1=0.98, v_repeat=N)` |
| **叶卡 UV** | **v=0 是脊线（对折边），v=1 是翼的自由边，U 跨 0→2 平铺两次** | `_leaf_card()` |
| **顶点色 R** | 恒 0（预留） | `_wind_color()` |
| **顶点色 G** | 叶片 = 每张卡片的随机相位 ∈ [0,1)；木质 = 0 | `_wind_color()` |
| **顶点色 B** | 恒 0（预留） | `_wind_color()` |
| **顶点色 A** | **归一化高度 `clamp(z / height, 0, 1)`**，= 风弯曲权重 | `_wind_color()` |
| **顶点色写出格式** | RGBA 四分量，`ByPolygonVertex` + `IndexToDirect`，层名 `WindData` | `fbx_writer._geometry_node()` |
| **法线** | `ByPolygonVertex` + `Direct` | 同上 |
| **节点层级** | 一个 Null 根 `<Base>` + 若干 Mesh 子节点 `<Base>_LOD0/1/2` | `export_lod_fbx()` |
| **LOD 策略** | **叶片在所有 LOD 完全一致，减面只发生在木质部分** | 生成器 `lod_specs` |

### 3.1 关于顶点色 A 通道的两个坑

**（1）它是数值，不是颜色。** 导入引擎时必须走 Linear，不能走 sRGB，否则 gamma 变换会污染数据。这一条要写进交付说明。

**（2)必须 clamp。** 枝条末端上翘、叶卡外扩都可能让顶点 z 略微超过声明的 `height`，不 clamp 就会出现 A > 1。`verify()` 里的断言也必须用同样的 clamp 逻辑比对，否则会误报。

### 3.2 为什么 LOD 只减木质

实测参考资产：叶片四边形数在 LOD0/1/2 三级中恒为 266，减面 772 → 152 → 48 全部发生在树干和枝条上。原因很直白：**针叶树的轮廓由叶片决定，树干本来就被挡住了**。LOD2 的 48 = 6 边 × 8 段，就是一根光秃的锥形管。

这个策略对绝大多数植被都成立。草和花更极端 —— 它们几乎没有木质部分，LOD 只能靠减少个体数量或降低卡片数，见 §6。

## 4. 五个阶段

### 阶段 1 · 逆向参考资产

**目标**：产出一份 `spec_<品类>.md`，把下面 14 个问题全部回答出来。没有这份 spec 就开始写生成器，一定会返工。

```bash
python tools/inspect_fbx.py mesh/<参考>.FBX        # 结构总览
python tools/analyze_tree_fbx.py mesh/<参考>.FBX   # 拓扑/UV/顶点色语义
python tools/analyze_layout.py mesh/<参考>.FBX     # 骨架布局规律
```

**必须回答的清单：**

| # | 问题 | 从哪里看 | 判读要点 |
|---|---|---|---|
| 1 | FBX 版本、是否二进制 | `inspect_fbx` | <7500 用 13 字节哨兵，≥7500 用 25 字节 |
| 2 | `UnitScaleFactor` 和 `UpAxis` | `inspect_fbx` | 2.54 = 原始单位是英寸；1.0 = 厘米 |
| 3 | 真实尺寸（米） | `analyze_tree_fbx` | 决定生成器的 `height` 默认值 |
| 4 | LOD 数量与命名 | `inspect_fbx` 的 Model 列表 | `_LOD0/1/2` 后缀是 Unity 自动建 LODGroup 的约定 |
| 5 | 每级 LOD 的三角面数 | `inspect_fbx` | 抄成生成器的面数预算 |
| 6 | 拓扑：quad / tri / ngon 比例 | `inspect_fbx` | 全 quad 说明是 3ds Max/Maya 手工建模流程 |
| 7 | 材质槽数量、名称、顺序 | `inspect_fbx` 的 Material 列表 | 顺序即 `mat_ids` 的取值 |
| 8 | 各槽的面数分布，以及**在三级 LOD 间怎么变** | `analyze_tree_fbx` | **这里能直接读出 LOD 策略** |
| 9 | UV 通道数与名称 | `inspect_fbx` | |
| 10 | 各材质槽的 UV 范围与唯一 UV 点数 | `analyze_tree_fbx` | 叶片只有十几个唯一 UV 点 ⇒ 是卡片贴图，不是展开 |
| 11 | 叶片连通分量数、每个分量的顶点数 | `analyze_tree_fbx` | **6 顶点/2 面 = V 形对折卡；4 顶点/1 面 = 平面卡；更多 = 别的原语** |
| 12 | 叶片是否共面 | `analyze_tree_fbx` 的"共面比例" | 100% 共面但有 6 顶点 ⇒ 两个平面 quad 折成 V |
| 13 | 顶点色四通道的取值范围 | `analyze_tree_fbx` | 恒定通道 = 未使用 |
| 14 | 顶点色各通道**与高度的相关系数** | `analyze_tree_fbx` | 接近 ±1 ⇒ 该通道存的是归一化高度（风弯曲权重） |

**样板答案（松树）供对照：**

- 4.94 m 高，冠幅 2.87 m，原始单位英寸
- LOD0/1/2 = 2076 / 836 / 628 三角面，全四边形
- 2 个材质槽：`Default_Bark` + `Default_Leaves`
- 树皮 quad 772→152→**48**，叶片 quad **266→266→266**（LOD 只减树干）
- 133 个叶片连通分量，每个恰好 6 顶点 / 2 四边形，100% 共面 ⇒ V 形对折
- 叶片只有 16 个唯一 UV 点，U 跨 0→2
- 顶点色 A 与高度相关系数 **+0.988**（树皮）/ **+0.993**（叶片）⇒ A = 归一化高度
- 7 层轮生枝，位于树高 22%~99%，每层 5 根，共 35 根
- 树冠包络近似线性：`Rmax ≈ 1.73 − 1.29 × (z/H)`

> **额外提醒**：如果参考资产的顶点色某个通道与高度相关系数是 **负** 的，或者与**到主干的水平距离**相关，说明它编码的是别的东西（常见的是"到枝条根部的距离"用于叶片摆动衰减）。`analyze_tree_fbx.py` 目前只算与 Z 的相关性，遇到这种情况要顺手加一个与径向距离的相关性统计。

### 阶段 2 · 写生成器

新建 `tools/<品类>_gen.py`。骨架照抄 `pine_gen.py`。

#### 2.1 网格容器接口

```python
mesh = TreeMesh()
vi = mesh.add_vert((x, y, z))                    # 返回顶点索引
mesh.add_poly(idxs, mat, uvs, nrms, cols)        # idxs 逆时针；uvs/nrms/cols 与 idxs 等长
mesh.stats()   # -> dict(verts, polys, tris, bark_polys, leaf_polys)
```

注意 **UV / 法线 / 顶点色都是 per-polygon-vertex**，不是 per-vertex。同一个顶点被两个面引用时可以有不同的 UV 和法线，这正是硬边和 UV 接缝的实现方式。

#### 2.2 现成原语

```python
_tube(mesh, spine, radii, sides, height_ref, u0=0.02, u1=0.98, v_repeat=1.0)
```
沿 `spine`（N×3 折线）生成锥形管，`radii`（N 个）逐环半径，`sides` 边数。内部用**平行传输**推进参考向量，这是避免管体沿长度方向扭转的关键 —— 每个环独立用 `_frame()` 重新起算会产生肉眼可见的麻花。返回新增面数。

```python
_leaf_card(mesh, origin, direction, side_hint, length, wing, fold_deg, height_ref, phase)
```
V 形对折卡片。`origin` 是脊线起点，`direction` 是脊线方向，`side_hint` 决定翼展开的平面（会自动正交化），`fold_deg` 是对折半角（越小翼越平）。产出 6 顶点 / 2 四边形，UV 自动按契约铺好。

#### 2.3 骨架算法选型

| 品类 | 骨架算法 | 说明 |
|---|---|---|
| **针叶树** | 轮生（whorl） | 沿主干每隔 h 生成一轮 n 根侧枝，长度按锥形包络衰减。**已实现** |
| **阔叶树** | 递归分枝 / 空间殖民 | 递归：每级按分叉角+长度衰减率生成子枝，深度 3~4 级。空间殖民论文公开，实现约百行，效果更自然但更慢 |
| **灌木** | 从根丛生 | 多根主枝从同一点以不同方位角发散，每根再递归 1~2 级。本质是"没有主干的阔叶树" |
| **草丛** | 丛生扇形 | 单点发散的曲线叶片，无木质部分。可以直接用**弯曲卡片**代替管+卡片 |
| **花** | 茎 + 花冠 | 一根细管做茎 + 若干花瓣卡片绕轴环形排布 + 一个花心（低边数球或圆盘） |

选型判据很简单：**看参考资产的连通分量结构**。木质部分是 1 个连通分量 ⇒ 有主干；是 n 个 ⇒ 丛生；完全没有木质材质槽 ⇒ 草。

#### 2.4 面数预算怎么控

先定预算，再反推参数。以松树为例：

```
目标 LOD0 ≈ 2076 三角面
  叶卡：133 张 × 2 quad × 2 tri = 532 tri     ← 先定叶卡数（决定轮廓）
  剩余 1544 tri = 772 quad 给木质
  主干：6 边 × 20 段 = 120 quad
  枝条：35 根 × 6 边 × 3 段 = 630 quad
  合计 750 quad ≈ 目标
```

`lod_specs` 是一个元组列表，每项对应一级 LOD。松树用的是 `(树干边数, 树干纵段, 枝条边数, 枝条纵段, 保留枝条比例)`：

```python
lod_specs = (
    (6, 20, 6, 3, 1.0),    # LOD0
    (6, 16, 4, 1, 0.55),   # LOD1：枝条降细分 + 只留 55% 最粗的
    (6, 8,  0, 0, 0.0),    # LOD2：枝条全砍，只剩一根光杆主干
)
```

新品类可以自定义这个元组的字段含义，只要 `generate(p, lod)` 会解包它。

#### 2.5 三条容易忽略的实现细节

**（1）叶片必须用独立的 rng。** 三级 LOD 的叶卡要完全一致，但木质部分的生成会消耗随机数。松树的做法是叶卡另起一个 `np.random.default_rng(p.seed + 991)`，和主 rng 隔离。不这么做，切 LOD 时叶片会跳变。

**（2）顶端要补卡片。** 主干尖端如果没有叶片覆盖，渲染出来是一截光秃的杆子，非常显眼。松树用 `apex_cards` 参数在树顶补一圈朝上的卡片。任何有中央主轴的品类都会遇到这个问题。

> 中间踩过一次坑：最初试图让顶层轮生枝只向下抖动来盖住树尖，结果树的下半段露出了主干。补顶端卡片才是对的解法，抖动应该保持对称。

**（3）叶卡要沿枝条铺满并超出末端。** 卡片中心放在 `pos - cdir * length * 0.35`，这样卡片会向前延伸 0.65 倍长度，能盖住枝条末端。卡片沿枝条的分布区间从 `card_span_start`（约 0.12）到 1.0。

### 阶段 3 · 导出 FBX

新建 `tools/build_<品类>.py`，照抄 `build_pine.py`。

#### 3.1 payload 格式

```python
def to_fbx_payload(mesh, scale_cm=100.0):
    """米 / Z-up  ->  厘米 / Y-up"""
    pos = [(p[0]*scale_cm, p[2]*scale_cm, -p[1]*scale_cm) for p in mesh.pos]
    nrm = [(n[0], n[2], -n[1]) for n in mesh.nrm]
    return dict(pos=pos, polys=mesh.polys, uv=mesh.uv, nrm=nrm,
                col=mesh.col, mat_ids=mesh.mat_ids)
```

**法线也要转换，而且不能带缩放。** 漏掉法线转换的症状是光照方向整体错乱，但几何看起来完全正常，很难一眼发现。

#### 3.2 写出

```python
from fbx_writer import export_lod_fbx

MATERIALS = [("Default_Bark",   (0.349, 0.180, 0.067)),
             ("Default_Leaves", (0.204, 0.588, 0.176))]

size = export_lod_fbx(path, base_name,
                      [to_fbx_payload(m) for m in lods],
                      MATERIALS, unit_scale_cm=1.0)
```

材质列表的**顺序**决定 `mat_ids` 的语义，必须和生成器里的 `MAT_BARK=0 / MAT_LEAF=1` 对上。

#### 3.3 什么时候需要动 `fbx_writer.py`

绝大多数品类不需要。需要动的情况：

- **材质槽超过 2 个**（比如花要 茎 / 叶 / 花瓣 / 花心 四个槽）—— 只需要往 `MATERIALS` 里加，写出器本身支持任意个
- **要把贴图正式关联进 FBX** —— 需要新增 `Texture` 和 `Video` 节点，以及 `OP` 类型的 Connection（`C: "OP", texture_id, material_id, "DiffuseColor"`）。参考资产没这么做（贴图在引擎侧挂），所以目前也没实现
- **要多 UV 通道** —— `_geometry_node()` 里加第二个 `LayerElementUV`，`TypedIndex` 递增，并在 `Layer` 里登记
- **要骨骼/动画** —— 不建议，风动画走顶点色就够了

### 阶段 4 · 校验

三层，缺一不可。

#### 4.1 回读断言（每次生成都跑）

`build_pine.py: verify()` 的断言清单，新品类照搬：

```python
assert tris == expect["tris"]                  # 面数与生成器统计一致
assert quads == len(polys)                     # 全四边形，无三角面
assert bark == expect["bark_polys"] and leaf == expect["leaf_polys"]
assert alpha_err < 1e-3                        # 顶点色 A == clamp(y/height)
```

注意 `verify()` 收的是 **Y-up 厘米**下的高度，所以传 `p.height * 100.0`，并且取 `Pp[vi][1]`（y 轴）而不是 z 轴。

#### 4.2 第三方加载器独立校验

```bash
python tools/validate_with_ufbx.py exports/<资产>.fbx
```

**硬性验收标准：**

| 项 | 要求 |
|---|---|
| 解析警告数 | **0** |
| 坐标轴 | `up=POSITIVE_Y front=POSITIVE_Z right=POSITIVE_X` |
| 单位 | 1 单位 = 0.01 米 |
| 层级 | Null 根 + `_LOD0/1/2` |
| 面 | 全四边形 |
| 顶点色 | `value_reals = 4`（说明 Alpha 保留了，不是被降成 RGB） |
| Alpha 与高度相关系数 | ≈ +1.0000 |

> **已知问题**：ufbx 的 Python 绑定在访问 `node.parent` 和 `mesh.instances[i]` 时会段错误。**参考资产在完全相同的位置崩溃**，所以是绑定库缺陷，与被检文件无关。`validate_with_ufbx.py` 已经绕开这些访问器，改成从 `scene.root_node` 递归 `children` 并把信息拷进普通 Python 列表再处理。新写校验脚本时不要重新踩这个坑。

#### 4.3 渲染验收

### 阶段 5 · 渲染验收

`tools/render_hq.py` 是一个纯 numpy 的软件渲染器，不需要 GPU 也不需要 DCC。

#### 5.1 贴图

`tools/gen_tree_textures.py` 程序化生成针叶 / 树皮 / 地面三张图。新品类照抄这个模式，关键是**贴图布局必须匹配 UV 契约**：

- **叶片贴图**：v=0 是脊线，所以针叶/花瓣要从**图像底边**生根、向上展开。底边附近必须不透光（加一层密集短针叶），否则对折处会漏出背景。
- **树皮贴图**：竖向拉伸的噪声 + 裂纹，各向异性高斯模糊（`GaussianBlur((1.0, 9))` 这种 x/y 不等的半径）是最省事的做法。
- **采样约定**：`render_hq.sample()` 里 `v=0` 对应图像**底边**（`y = (1-v) * h`）。

> 一个很好用的交叉验证：**用同一张叶片贴图去渲染参考资产**。如果贴上去严丝合缝，说明 UV 布局逆向对了。松树这一步验证通过，所以 `hq_compare.png` 是真正的同贴图、同光照对比。

#### 5.2 渲染器接口

```python
import render_hq as R

mats = [R.Material(R.load_texture("bark.png"), color=(1,.95,.88), spec=0.03),
        R.Material(R.load_texture("leaf.png"), two_sided=True, alpha_cutout=True,
                   cutoff=0.45, translucency=0.55),
        R.Material(R.load_texture("ground.png"), spec=0.0)]

dm = R.from_tree_mesh(tree_mesh)                       # TreeMesh -> 可绘制网格
gm = R.ground_mesh(size=120.0, repeat=70.0, mat=2, div=24)
img = R.render([dm, gm], mats, width=880, height=1150, ss=2,
               azimuth=38, elevation=7, target=(0,0,2.5), radius=3.1,
               shadow_res=1400, shadow_bounds=(lo, hi),
               fog=0.0028, exposure=1.5, shadow_strength=0.30)
R.save_png(img, "out.png")
```

叶片材质**必须** `two_sided=True` + `alpha_cutout=True`，否则卡片会渲染成实心四边形。

其他工具函数：`R.transform(mesh, translate, rot_z, scale)` 摆放实例，`R.apply_wind(mesh, t, amplitude, freq, flutter)` 做风形变，`R.label_grid(images, labels, cols)` 拼对比图。

**`shadow_bounds` 一定要传主体的包围盒**，不传的话正交阴影体积会被巨大的地面撑开，阴影分辨率被耗光，看起来就像没有阴影。

#### 5.3 必出的四张图

| 图 | 用途 | 判据 |
|---|---|---|
| `hq_compare.png` | 参考 vs 生成，同贴图同光照 | 轮廓、疏密、比例是否同一物种 |
| `hq_lods.png` | 三级 LOD 并排 | **轮廓应该几乎看不出区别**，看得出就说明减错地方了 |
| `hq_variants.png` | 同参数换 seed | 有变化但不出现畸形个体 |
| `hq_wind_sheet.png` | 顶点色驱动的风形变关键帧 | 根部不动、梢部摆幅最大 |

风动画关键帧要**取四分之一相位处**（`frames//8, 3*frames//8, ...`）。取整数分之一处会正好落在摆动的过零点上，四帧看起来一模一样。

## 5. 踩坑清单

按"会浪费多少时间"排序。

### FBX 格式

| 坑 | 症状 | 解法 |
|---|---|---|
| 文件尾格式不对 | 部分导入器报错、部分能读 | 尾部是：13 字节零哨兵 + 16 字节 footer id + 补零到 16 对齐 + 4 字节零 + 4 字节版本号 + 120 字节零 + 16 字节固定魔数 |
| 节点 end offset 算错 | 解析器读到一半跑飞 | `serialize()` 必须先递归算出所有子节点长度再回填 offset；有子节点时末尾要加 13 字节零哨兵，且这 13 字节**计入** end offset |
| 数组属性没压缩 | 文件体积膨胀数倍 | `_arr()` 里 zlib 压缩后比原始短才用压缩，并在头里标 `encoding=1` |
| 混淆 `ByPolygonVertex` 和 `ByVertex` | UV / 法线错位 | 本项目统一 `ByPolygonVertex`。数组长度 = 所有面的顶点数之和，不是顶点数 |
| 顶点色被降成 RGB | Alpha 数据丢失 | 检查 ufbx 报的 `value_reals` 必须是 4 |

### 几何

| 坑 | 症状 | 解法 |
|---|---|---|
| 管体扭转 | 树干上的 UV 呈麻花状 | `_tube()` 里用平行传输推进参考向量，不要每环重新 `_frame()` |
| 树顶光杆 | 树尖露出一截裸树干 | 补 `apex_cards` 朝上的卡片。**不要**靠改轮生层抖动来盖 |
| 顶点色 A > 1 | `verify()` 断言失败 | 生成和校验两侧都要 `clamp(0,1)` |
| 切 LOD 时叶片跳变 | LOD 过渡闪烁 | 叶卡用独立 rng |

### 渲染器

| 坑 | 症状 | 解法 |
|---|---|---|
| 正交投影下 `w` 恒为 1 | 阴影贴图完全失效（深度全存成 1） | 正交要用 **NDC z** 当深度，透视才用 `w` |
| 跨越相机平面的三角形被整块剔除 | 地面上出现大块空洞 | 光栅化前做**近平面裁剪**（Sutherland-Hodgman 对 `w >= near` 裁），不要靠加密网格绕过 |
| 阴影正交体积被地面撑开 | 阴影糊成一片或干脆没有 | 传 `shadow_bounds` 只包住主体 |
| 叶卡渲染成实心方块 | 树看起来像一堆纸板 | 材质要 `alpha_cutout=True` |
| 贴图颜色偏暗 | 整体发闷 | `load_texture()` 已做 sRGB→线性（`**2.2`），所以贴图源文件的数值要按 sRGB 来定，别按线性定 |

### 环境

| 坑 | 症状 | 解法 |
|---|---|---|
| `bpy` 装不上 | `pip index versions bpy` 找不到分发 | PyPI 上 bpy 只有绑定 Python 3.11（Blender 4.x）和 3.13（5.x）的 wheel。3.12 没有匹配版本。这也是本项目走纯 Python 路线的直接原因 |
| `ndarray.ptp()` 报 AttributeError | numpy 2.x | 改用 `np.ptp(a)` |
| PowerShell 改源文件把中文弄乱码 | `SyntaxError: invalid non-printable character` | **不要用 `Set-Content` / `sed` 改源文件**，用编辑工具 |
| `head` 命令不存在 | PowerShell 下 | 用 `Select-Object -First N` |

## 6. 各品类配方

下面是根据松树的经验外推的起点，实际参数以阶段 1 的逆向结果为准。

### 6.1 阔叶树

- **骨架**：递归分枝。参数：分叉数（2~3）、分叉角（30~50°）、长度衰减率（0.6~0.75）、半径衰减率（约 `子半径 = 父半径 × 0.7`）、递归深度 3~4
- **原语**：`_tube` 复用；叶片改成**单 quad 平面卡**或 V 形卡（看参考资产的连通分量顶点数）
- **叶片朝向**：阔叶要朝上（受光面），不像针叶那样下垂。`card_pitch` 取负值
- **面数预算**：木质占比更高（枝干可见），大约 木质 : 叶片 = 6 : 4
- **LOD**：仍然只减木质，但递归末级的细枝可以整层砍掉

### 6.2 灌木

- **骨架**：从根部一点发散出 5~9 根主枝，每根再递归 1~2 级。本质是去掉主干的阔叶树
- **注意**：没有中央主轴，所以不需要 apex 卡片，但要注意根部所有枝条聚在一点会产生密集的自相交，可以给每根主枝一个小的起点偏移

### 6.3 草丛

- **骨架**：无。单点发散
- **原语**：**弯曲卡片** —— 需要新写。一片草叶是沿一条二次贝塞尔曲线扫掠的带状 quad 条（4~6 段），根部宽、尖端收窄。不要用 V 形对折，草叶是薄片
- **材质槽**：只有一个（叶片）。`MAT_BARK` 槽空着或者干脆只写一个槽
- **顶点色 A**：仍然是归一化高度，但"高度"是单株草的高度，不是丛的高度
- **LOD**：木质无可减，只能减**草叶数量**。这是唯一一个违反"LOD 不减叶片"原则的品类。LOD1 保留 60%、LOD2 保留 35%，并且降低每片草叶的段数（6 段 → 3 段 → 1 段变成平板）
- **面数预算**：单丛 LOD0 控制在 200~400 三角面，因为场景里会铺成千上万丛

### 6.4 花

- **骨架**：一根细管做茎（`_tube`，4~6 边），顶端一个花冠
- **原语**：花瓣 = 单 quad 或 2×2 网格的微弯卡片，绕轴环形排布，可以分 2~3 轮内外错开；花心 = 低边数圆盘或半球
- **材质槽**：4 个 —— 茎 / 叶 / 花瓣 / 花心。`export_lod_fbx` 的 `MATERIALS` 直接加即可
- **顶点色**：花瓣的 G 通道相位要**按花朵分组**而不是按花瓣分组，否则同一朵花的花瓣会各自乱抖
- **LOD**：减花瓣的细分（2×2 网格 → 单 quad），花朵数量不减

### 6.5 通用：一个品类需要多少参数

松树用了 28 个参数 + seed。经验值：

- 整体尺寸 2~3 个（高度、根部半径、锥度）
- 骨架 5~8 个
- 叶片 6~8 个（尺寸、抖动、朝向、密度）
- LOD 分档 1 个元组
- 随机性 3~5 个 jitter

超过 40 个参数说明抽象层次不对，应该拆成两个品类。

## 8. 批量作业组织

### 8.1 参数库

每个品类维护一个 JSON，把调好的参数组存下来，而不是散落在代码的默认值里：

```json
{
  "pine_tall":   {"height": 6.2, "whorl_count": 9,  "crown_radius": 1.7},
  "pine_young":  {"height": 2.4, "whorl_count": 5,  "crown_radius": 1.1},
  "pine_sparse": {"height": 4.9, "whorl_count": 7,  "cards_base": 3.5}
}
```

生成时 `replace(PineParams(seed=s), **preset)`。这样"生成 500 棵，3 种形态各若干，每种 N 个 seed"就是一个二重循环。

### 8.2 命名

`<品类><形态>_<序号>` → `ProcPine_03`，FBX 内的 Null 根节点名与文件名一致，Mesh 子节点加 `_LOD{i}`。

### 8.3 吞吐

松树单线程 156 ms/棵（含 3 级 LOD 生成 + FBX 写出），纯 Python 未做优化。用 `multiprocessing.Pool` 铺开即可，生成过程之间完全无共享状态。一台普通机器每分钟出几千个没问题。

**渲染才是瓶颈**，不是生成。软件渲染器一张 880×1150 SSAA×2 的图要 15~20 秒。所以验收图只对每个品类的代表性个体出，不要每个资产都渲。

### 8.4 一个品类一个工作单元

建议每个品类独立成一次提交/一个 PR，包含 §7 交付物清单里的全部内容。不要一次改多个品类 —— 共用的基础设施（`fbx_writer`、`render_hq`）一旦改动会同时影响所有品类，需要全量回归。

## 附录 A · API 速查

### 读 FBX

```python
from inspect_fbx import parse
from analyze_tree_fbx import unpack_geometry, get_name

root, version = parse("x.fbx")
objects = root.first("Objects")
geos = objects.find("Geometry")
P, polys, mats, uvs, uv_idx, cols, col_idx = unpack_geometry(geos[0])
# P: [(x,y,z)]  polys: [[vi,...]]  mats: 每面一个槽号
# uvs/cols 是扁平数组，配合 uv_idx/col_idx 索引：uvs[i*2], cols[i*4+3]
```

`Node` 的接口只有两个：`node.find(name) -> [Node]`、`node.first(name) -> Node|None`，属性在 `node.props`。

### 写 FBX

```python
from fbx_writer import export_lod_fbx
export_lod_fbx(path, base_name, lod_payloads, materials, unit_scale_cm=1.0, creator="...")
# lod_payloads: [dict(pos, polys, uv, nrm, col, mat_ids)]，索引即 LOD 级别
# materials:    [(名称, (r,g,b))]
# 返回写出的字节数
```

需要手搓节点时：`N(name, *props, children=[])`，属性是 `(类型字符, 值)` 二元组。类型字符：`Y`=int16 `C`=bool `I`=int32 `F`=float `D`=double `L`=int64 `S`=字符串 `R`=裸字节 `d/f/i/l`=对应类型的数组。

### 生成

```python
from pine_gen import PineParams, generate, generate_lods, TreeMesh, MAT_BARK, MAT_LEAF
mesh  = generate(PineParams(seed=3), lod=0)
lods  = generate_lods(PineParams(seed=3))
stats = mesh.stats()   # dict(verts, polys, tris, bark_polys, leaf_polys)
```

### 渲染

```python
import render_hq as R
R.load_texture(path)                                    # -> (H,W,4) 线性空间
R.Material(texture, color, two_sided, alpha_cutout, cutoff, translucency, spec)
R.from_tree_mesh(tree_mesh)                             # TreeMesh -> DrawMesh
R.ground_mesh(size, z, repeat, mat, div)
R.transform(mesh, translate, rot_z, scale)
R.apply_wind(mesh, t, direction, amplitude, freq, flutter)
R.render(meshes, materials, ...)                        # -> (H,W,3) uint8
R.save_png(img, path)
R.label_grid(images, labels, cols)
```
